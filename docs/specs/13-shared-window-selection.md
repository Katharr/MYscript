# 顶部统一选窗与角色状态

## 用户确认的交互

- 顶部角色卡片是唯一执行窗口选择入口，点击卡片或复选框切换参与状态，立即保存；支持键盘空格。
- 每个角色都有独立的队长勾选项，互斥且不能取消唯一队长；与参与任务的选择互不连带。
- 有窗口时自动初始化一名队长；窗口排序和角色名称更新不改变队长身份。
- 所有业务使用同一选窗集合与队长。移除任务页的选择窗口按钮、角色页的重复选择与保存按钮、副本页的队长下拉框。
- 全选仅选择当前窗口；后续新窗口默认不选。清空允许零目标，业务开始按钮禁用，启动登录档案不受影响。
- 卡片第二行独立显示该角色的任务状态；文字与颜色共同表达运行、等待、完成、异常和停止。
- 顶部选择在启动检查、运行、停止和窗口批量操作期间锁定；状态和角色身份继续刷新，停止仍可使用。
- 组队任务启动检查队长是否参与；队长消失先请求停止，工作线程完全退出后才能重新指定，并输出提示。

## 目标与配置

`WindowSelection` 按 HWND 保存当前会话中的选择，不用列表序号推断角色身份；兼容首次读取旧序号配置。

- `targets.selected_hwnds`：明确的当前集合，空就是不执行；不会使用旧版“空列表表示全选”的兜底。
- `targets.captain_hwnd`：全局队长身份；派生各业务命名空间的旧 `captain_index`，未参与时为 -1。
- `targets.window_handles`：只存在于 runner 配置副本的启动快照；固定顺序，不随界面变化而更新。
- 启动快照中的任意窗口缺失，解析返回空集合，不能压缩队长索引或改选其它窗口。
- 句柄失效后不猜角色、不把新窗口当成原窗口。重新打开游戏产生的新窗口需要重新选择。
- 配置保存合并最新配置，并走既有 `save_config` 护栏；保存失败还原界面与内存选择。

## 状态上报

输入会话在执行阶段确认激活成功时上报当前业务；一条龙每窗 driver 显式上报自己的业务，因此不同角色可以同时显示宝图和运镖。轮转完成和集合等待独立上报，工作线程只更新 runner 的线程安全状态表，不操作 Qt，也不解析自然语言日志。启动检查不发布运行状态。

停止请求显示“停止中”，线程实际结束后显示结束状态；已经确认完成的角色不会因其它角色停止而改成停止中。尚未获得执行机会的窗口显示等待，未参与窗口保持空闲。

## 视觉与验收

- 经紧凑布局预览确认，卡片固定宽 180px、基础高度 68px、间距 6px，靠左排列，不随剩余空间拉伸；两个角色仅占 366px。
- 两行布局：第一行参与勾选与角色名，第二行检测灯、任务状态与右侧队长勾选。保留原字号和 20px 勾选框。
- 800px 主窗口可容纳三张、1120px 可容纳五张；仅溢出时显示横向滚动条并增加对应高度。窗口缩放后及时重新计算，不保留空白滚动区。
- 卡片高度兼顾控件最小高度，防止状态行被压扁；角色名与状态按实际宽度省略，悬停和无障碍名称保留全文。
- 检测状态灯、参与任务的边框和队长勾选分别表达独立含义。
- 新增核心目标/状态回归及 Qt 统一选窗回归，覆盖空选、重排、窗口新增/消失、队长互斥、锁定、保存失败和逐窗状态。
- 明暗主题、两种窗口尺寸、十二个页面及零/多窗口、日志展开组合，在四档缩放下进行离屏布局检查。
- 紧凑版实际组件截图覆盖浅色双角色/三角色/五角色与深色三角色；四档缩放共 240 个页面布局场景无裁切或溢出问题。
- 自动回归额外覆盖卡片不拉伸、三/五张容量、溢出滚动与加宽后恢复紧凑高度，以及长状态的全文保留。
- 最终全量回归：`python -X faulthandler -m unittest discover -v -t . -s tests`，600 项全部通过。
- 不使用真实游戏窗口、不执行实际输入、不写真实用户配置；真实游戏与多显示器交互仍需实际环境复核。
