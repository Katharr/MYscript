# 角色与窗口：尺寸组管理与选中尺寸恢复

## 页面与交互

- 顶部角色条继续作为唯一选窗与队长入口，尺寸列表仅展示角色、当前尺寸和与基准的对比。
- 有游戏窗口时页面顺序为窗口操作、窗口尺寸、启动与登录、危险操作。零窗口或登录运行时启动区移到最前，开始/停止按钮位于档案列表前。
- 主体使用单个纵向滚动区，工具栏整项换行，启动档案不再建立嵌套滚动。
- 尺寸区提供最多三个组的切换、记录参照角色尺寸、管理/删除尺寸组及“恢复选中尺寸（数量）”。删除只移除记录及归属指针，保留模板文件。
- 一个选中角色直接作为记录参照；多个选中角色明确选择参照。满组替换取消、参照窗口变化和保存失败均不提交草稿。
- 标定中心只读展示当前尺寸组，提供跳转入口；尺寸操作集中到角色与窗口。
- 无选择、无有效基准或检测失败时禁止恢复。任务启动/运行/停止、标定编辑及窗口批量操作期间禁止尺寸修改。

## 执行与状态

- 普通后台扫描附带只读窗口尺寸；最小化窗口读取正常还原矩形，不唤窗、不截图、不执行 OCR。尺寸读取失败不改变窗口身份与存在状态。
- 点击恢复时复制配置，并使用 WindowSelection.snapshot 固定 HWND 集合及顺序。不会使用旧序号兜底；任一目标在执行前消失则整批拒绝。
- 沿用主窗口窗口操作线程、Qt 信号及状态门禁。操作开始即锁定顶部选择、尺寸编辑和新任务，线程不操作 QWidget。
- 实际尺寸通过 core.window.restore_targets_size 返回；激活失败跳过调整，单窗异常不阻断其它目标。结果回主线程刷新尺寸列表并重新扫描。
- 明确报告成功数/目标数、实际可达尺寸、部分失败、目标失效和后台错误。只有显式点击恢复才调整游戏窗口。
- 尺寸真源保持 calib_profiles；targets.base_size 仍由既有尺寸组逻辑派生，模板存储契约不变。

## 验证

- tests/test_qt_window_sizes.py 覆盖固定目标、目标消失、激活失败、逐窗异常、最小化尺寸、基准切换、记录/替换事务、后台锁定、反馈和页面跳转。
- tests/test_qt_calibration.py 的尺寸组事务回归迁移到 WindowSizePanel；关闭窗口回归先展开危险操作区。
- 启动登录模拟运行服务明确声明空闲；既有启动身份回归中两条队长断言在原提交的隔离副本也失败，更新为现有“默认首窗、顶部统一指定”语义，产品队长逻辑未修改。
- 布局使用真实 Qt 组件和虚拟角色，检查明暗主题、800×640 / 1120×720、零/三个窗口，在 100%、125%、150%、200% 下的溢出与控件高度，并查看实际截图。
- 全量回归使用 python -X faulthandler -m unittest discover -v -t . -s tests。真实客户端尺寸恢复与比例限制需在游戏环境复核。
- 最终全量 619 项通过；四档缩放共 32 个布局场景未发现检查范围内的控件高度不足或横向溢出，另审阅了尺寸管理弹窗。最后的弹窗文案调整通过对应交互回归。
