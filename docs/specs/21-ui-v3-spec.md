# UI 3.0 浅色工作台改造规格

状态：用户已接受浅色 3.0 基准；首轮生产改造后的 Windows 真机验证发现视觉与操作问题，尚未验收通过。2026-11-13 修正要求已整理为[真机视觉修正方案](22-ui-v3-polish.md)，待实施；标定交互优化已移出本轮。

## Problem Statement

界面按钮繁多、分布零散，任务入口与参数不易定位。各轮视觉探索产生了相互冲突的文档，旧版深色、Tk 迁移步骤和被否定方案容易被误读为当前要求。

用户已选择浅色 3.0 工作台，并确认单项任务标签页与通用工具成组操作；需要将这些决定固化为一致、可长期维护的设计和实施范围。

## Solution

以浅灰导航、白色工作区、蓝色选中态和主按钮建立统一桌面界面。保留全局角色条、中间业务页和右侧全局日志；窗口快捷操作常驻，任务页集中表达配置、状态与启停。

视觉数值与组件规则统一引用 [UI 3.0 视觉与布局规范](../视觉设计规范.md)。已被替代的文档移到归档目录，当前索引只指向有效规则。

## User Stories

1. 作为使用者，我希望默认看到浅色界面，以便在日常桌面环境下辨认内容。
2. 作为使用者，我希望同类按钮、输入框和列表风格一致，以便快速识别操作。
3. 作为使用者，我希望导航按任务与管理分组，以便找到所需功能。
4. 作为使用者，我希望当前导航有明确选中态，以便知道自己所在页面。
5. 作为使用者，我希望顶部统一选择执行角色，以便所有任务使用同一目标集合。
6. 作为使用者，我希望清楚区分角色参与状态、运行状态与队长，以免误判操作对象。
7. 作为使用者，我希望运行期间目标保持锁定，以免执行到错误角色。
8. 作为使用者，我希望切换页面后仍能找到唤出、全关与日志，以便随时处理窗口。
9. 作为使用者，我希望全关先确认，以便避免误关游戏窗口。
10. 作为使用者，我希望一条龙任务展示顺序、启用、模式和状态，以便确认接下来会执行什么。
11. 作为使用者，我希望在任务附近修改参数与运行模式，以便减少查找入口。
12. 作为使用者，我希望执行摘要与开始 / 停止按钮固定可见，以便内容滚动时仍能控制任务。
13. 作为使用者，我希望明确看到演练、实战与缺少标定，以便正确判断启动条件。
14. 作为使用者，我希望单项任务以标签页展示，以便直接看到并切换各项任务。
15. 作为使用者，我希望标签切换同时更新参数和启动按钮，以免配置与执行名称错位。
16. 作为使用者，我希望切回任务后保留其配置，以便比较和调整不同任务。
17. 作为键盘使用者，我希望能通过方向键切换任务标签，并看到焦点位置，以便完整操作界面。
18. 作为使用者，我希望一键组队与一键解散放在同组，以便处理相关队伍操作。
19. 作为使用者，我希望整理背包与管理物品放在同组，以便完成背包相关工作。
20. 作为使用者，我希望窄窗口能滚动或重排内容，以免控件和文字被挤坏。
21. 作为使用者，我希望日志可展开与收起，以便按需让出任务配置空间。
22. 作为使用者，我希望阅读旧日志时新消息不会抢走滚动位置，以便排查问题。
23. 作为使用者，我希望切页和调整窗口不会丢失日志或任务状态，以便持续观察运行。
24. 作为使用者，我希望原有自由点击、标定、尺寸组、登录及物品管理继续可用，以免改界面丢失功能。
25. 作为使用者，我希望在实际 Windows 窗口与系统缩放下验证最终结果，以便确认真实使用体验。
26. 作为维护者，我希望只有一份有效视觉基准和清晰文档索引，以免后续实现重新采用过时方案。

## Implementation Decisions

- 保留 PySide6 Qt Widgets 技术栈、现有主题层、主窗口、任务页面、全局选窗服务与运行服务。视觉改造不新增业务架构、配置结构或前后端接口。
- 主题层集中管理颜色、字体、间距与尺寸；默认浅色，既有用户偏好兼容。具体令牌与参考尺寸由视觉规范单独维护，本规格不重复缓存。
- 主窗口组织为导航、全局角色条、业务内容和右侧全高日志。顶栏固定相邻的唤出、全关与日志操作；日志使用同一展开 / 收起按钮，取消装饰竖线、面板内重复收起入口及单独窗口管理入口。
- 统一选窗集合、队长身份与运行快照沿用现有契约；角色参与与队长互斥规则按现有业务实现，不照搬 HTML 演示的简化联动。
- 日常一条龙采用连续执行清单和固定底部执行栏，保留顺序、启用、模式、状态、配置及时间上限。演练安全默认、预检查与停止中状态保持兼容。
- 单项任务采用五个横向标签，次序为宝图、运镖、秘境降妖、刷副本、秒装备。复用既有页面和配置，切换同步更新启动对象；运行 / 停止期间锁定切换。
- 通用工具分队伍与背包两个功能组，每组两个直接动作；组队与解散共享队伍语义，整理与物品管理共享背包语义。保留原任务入口与前置检查。
- 页面内容独立滚动，底部主操作保留。窄窗允许标签横向滚动、工具组换行与日志覆盖展开，常驻窗口按钮始终可达。
- 全局日志继续复用单一消息出口、有界缓存、来源筛选与跟随状态。调整展示位置和视觉不能改写原消息或引入重复消费。
- 配置浮层继续使用原有草稿、保存、失败回滚及标定事务；界面持久化与业务配置保持现有边界。
- 文案使用控件名、状态、错误和必要安全提醒；解释性设计文字、原型浮动底栏、虚构角色与模拟事件不进入正式界面。
- 旧迁移步骤、视觉探索和一次性交接归档；当前文档入口只链接本规格、视觉基准与仍有效的业务契约。

## Testing Decisions

- 本次文档交付检查索引、链接、归档完整性与要求一致性；不把现有生产界面视为已经完成 3.0，不为纯文档修改新建 UI 测试。
- 后续实现以现有 Qt 主窗口为主要验收入口，驱动导航、标签、工具动作与日志展开，检查用户可观察的内容、状态、启动对象和交互可达性；不锁定内部控件树或私有方法。
- 优先沿用 Qt 壳、统一选窗、右侧日志和可读性回归的既有做法：真实 Qt 组件、虚拟角色 / 句柄、模拟任务、临时配置与临时界面设置。原有业务契约回归继续覆盖配置隔离和运行目标锁定。
- 标签切换验证面板、参数状态和启动任务一致；鼠标、键盘与运行期间禁用都需覆盖。通用工具验证成组呈现且动作仍进入对应原有功能。
- 窗口按钮覆盖跨页、日志展开 / 收起、覆盖模式与确认取消；确认流程测试模拟窗口服务，避免实际关闭游戏。
- 布局验证普通与最小窗口、四档 Windows 缩放、长角色名、多角色、无角色、长错误、运行 / 停止中等状态；先保证文字与按钮完整，再核对视觉令牌。
- 日志验证筛选、复制、阅读位置、有界缓存、状态恢复与新日志提示；不因重绘丢失或重复消费消息。
- 自动检查与截图只能提前发现回归。最终必须由用户在 Windows 真机核验系统字体、缩放、焦点、真实窗口唤出 / 全关确认，以及演练和启停流程；不得用浏览器预览替代。

## Out of Scope

- 本次文档整理不实施生产 Qt 改造，不构建或发布新的可执行程序。
- 不重写任务、识别、输入、窗口身份、配置兼容、标定资产与队伍规则。
- 不添加新的暗色视觉方向、主题库、Web 容器、QML、Fluent Widgets 运行依赖或通用状态管理框架。
- 不恢复已否定的 B / C 布局，也不将 1.0 候选、2.0 / 2.1 探索作为当前默认。
- 原型未完整展示的参数与复杂管理页面继续保留现有能力；不按占位内容删减产品功能。

## Further Notes

### 2026-11-13 真机反馈后的修正

用户已确认继续沿用浅色 3.0；普通按钮使用清晰细边框，移除日志前竖线；任务标签只留文字下方短细选中线。日志必须与应用客户区同高，统一展开 / 收起入口，默认约占工作区三分之一宽并可拖动；窄窗全高覆盖且保留全局操作和急停。用户随后决定标定交互先不修改，以后再优化。

已通过正式 Qt 桌面窗口截图观察到小字缺笔 / 颗粒、顶栏边界不清、标签整排长基线、日志从角色条下方开始、双重收起入口和标定入口重复。截图观察不等于字体根因已定位，也不等于修正验收通过。

本轮实施范围、步骤和测试决定见[真机视觉修正方案](22-ui-v3-polish.md)。字体渲染方案由开发侧实测确定；这是实施调查任务，不再增加设计访谈。视觉要求以视觉规范为真源；标定继续沿用通用标定契约，先前访谈建议不作为当前改造要求。

最新视觉来源为浅色 3.0，包含本会话最后确认的任务标签与工具分组。原型快照分支为 `codex/prototype-ui-tabs-groups-20261113`；1.0 候选和此前各轮快照仍保留，供显式回溯。

本规格在项目长期文档中维护。尚未配置 to-spec 的 Issue 追踪器与分诊词汇，未发布 Issue；配置流程为 `/setup-matt-pocock-skills`。发布时按 skill 要求使用 `ready-for-agent`，但该状态不代表产品已经实施或真机验收通过。
