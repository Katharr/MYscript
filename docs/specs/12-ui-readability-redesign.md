# Qt UI 可读性与布局修正方案

日期：2026-10-16。公共控件规范、明暗主题与页面迁移已实施；下文保留设计依据和验收标准。

## 目标与设计依据

这个工具的主要使用过程是：选择角色和窗口 → 配置任务 → 启动 → 判断运行状态 → 必要时停止。
界面应优先帮助用户看清操作对象、当前选择、运行模式和任务结果。

据此建立四条规则：

1. 先保证文字完整、控件可识别和可点击，再分配装饰性留白。
2. 相关元素靠近，不同任务组拉开距离；同类控件使用相同的尺寸和状态规范。
3. 主要内容获得剩余空间；窗口变小时，重排、折叠次要区域或滚动，不继续压缩文字。
4. 颜色表达层级和状态，配合文字、形状与焦点提示，不能只靠颜色区分。

界面继续使用简短的控件名、状态与必要的错误/安全提醒。辅助用法放在工具提示中。

## 已核实的问题

检查范围：当前 `mhxy/qtui/` 实现、相关迁移规格，以及隔离配置的离屏布局检查。
检查使用 Qt Fusion、96 DPI、Microsoft YaHei UI，并显式加载系统字体；未启动游戏任务、未保存真实配置。
离屏结果用于确认结构性问题，不替代 Windows 真机缩放验收。

| 问题 | 证据 | 影响 |
| --- | --- | --- |
| 缺少统一的输入控件与复选框规范 | `theme.py` 主要定义按钮，页面各自设置输入框、复选框、表头样式 | 同类控件高度、内边距和状态不一致 |
| 内容超过可用高度时继续压缩控件 | 800×640 的副本页中，部分下拉框与复选框高度约 12–13，而字体度量高度约 16 | 文字被裁切、控件挤在一起 |
| 表格列宽优先级不合理 | `items_view()` 使用 ResizeToContents + StretchLastSection；空清单检查时名称列约 30、缩略图列约 43、路径列约 797（1120×720） | 核心名称难读，次要路径占据空间；列宽还会随数据变化 |
| 下拉框与管理操作争抢横向空间 | 自由点击页清单选择与新建、重命名、删除同行 | 小窗口下选择框被挤窄 |
| 复选框视觉和点击区域偏小 | 默认 indicator 约 14×14；各页未统一 indicator 与整行尺寸 | 未选状态难发现，操作目标小 |
| 控件边界与背景过于接近 | 当前 BORDER #2A313D 对 SURFACE #181C24 的计算对比度约 1.30:1 | 输入区域和控件轮廓不清楚 |
| 文本对比与整体观感需分别处理 | TEXT_DIM 对 SURFACE 约 5.51:1，正文约 14.16:1 | 问题集中在背景层级、控件边界和空间，不能只靠把所有文字变亮解决 |

## 字体、间距与缩放

以下尺寸是 100% 缩放下的逻辑尺寸起点，实际下限须结合字体度量计算。

| 项目 | 建议 |
| --- | --- |
| 正文、表单标签、列表名称 | 10.5–11 pt，96 DPI 时约 14–15 逻辑像素 |
| 辅助信息、时间、路径 | 约 13 逻辑像素，不能承担唯一的关键状态提示 |
| 页面标题 | 约 24 逻辑像素，中等字重 |
| 按钮、输入框、下拉框 | 常规最小高度 36；文字增大时允许增长 |
| 复选框整行 | 常规最小高度 32–36 |
| 普通列表行 | 常规最小高度 40–44 |
| 带缩略图的行 | 依据缩略图高度设置 64–80 起点 |
| 控件内部左右留白 | 10–12 |
| 标签与控件 | 16 |
| 方框与标签 | 10 |
| 表单行之间 | 12–16 |
| 功能组之间 | 24 |
| 页面边距 | 常规 24；紧凑窗口 16 |

实现要求：

- 建立统一的字体角色和间距令牌；避免页面任意混用 pt 与 px。不要通过增加字间距来掩盖布局问题。
- 单行控件的最小总高度取“规范下限”与“字体高度 + 上下内边距 + 边框”的较大者。
- 使用 QFontMetrics / QFontMetricsF 计算文本；多行内容按实际可用宽度计算高度。
- 同一表单统一标签对齐、垂直间隔与字段增长策略。长标签允许换行；空间不足时标签移到字段上方。
- 使用 QFormLayout 的 WrapLongRows 或明确的布局切换，避免标签和输入控件相互挤压。
- 区分内容高度和 QSS padding/border 后的总高度，避免叠加计算错误。
- Qt 6 使用逻辑坐标并处理 DPI；不再手工对所有尺寸重复乘系统缩放系数。
- 角色条按内容设置最小高度；无角色时使用紧凑状态，避免长期占用固定 70 高度。

### 字段宽度与滚轮交互（第二轮已实施）

| 字段类型 | 最小 / 最大逻辑宽度 |
| --- | --- |
| 普通数值输入 | 128 / 144 |
| 带增减按钮的数值 | 208 / 208 |
| 简短选项 | 176 / 208 |
| 名称选择 | 220 / 360 |
| 路径 | 240 / 640 |
| 急停主键 | 88 / 104 |

- 同组字段左对齐，有界增长；表格和日志继续利用可用宽度。设置表单最大宽度 720，分为窗口与识别、输入与外观、速度与节奏；保存按钮宽 128，与字段列对齐。
- 数值控件保留原生 QSpinBox/QDoubleSpinBox 的数值、范围、精度、键盘与校验接口，展示为“− / 数值与单位 / ＋”；两侧按钮宽 36、高度随控件，达到边界或只读时禁用。点击增减仍通过既有 editingFinished 保存入口提交。
- 所有数值框和闭合下拉框彻底忽略滚轮修改，包括已获得焦点的控件及 Ctrl+滚轮；事件交给上层滚动区域。输入框内部及增减按钮上滚轮亦可滚动页面。
- 滚动条宽 24，原生箭头按钮约 24×24，滑块最短 40；只替换绘制，不改变原生命中、拖动和滚动逻辑。角色条为加宽后的水平滚动条预留高度。
- 设置页单位贴近数值，范围放工具提示；活动页时间单位放入数值框后缀，0 仍按原数值保存并显示“不限”。

## 复选框

- 方框统一为 18–20 逻辑像素，边界约 2 逻辑像素，选中时显示清晰勾形。
- 未选、选中、半选（适用时）、悬停、键盘焦点和禁用分别定义状态。
- 未选时方框边界与相邻背景至少达到 3:1；选中时勾形与填充也至少达到 3:1。
- 点击方框或其标签均可切换，保留原生键盘 Space 和辅助技术语义。
- 列表行的“选中当前行”和“勾选参与执行”使用不同视觉反馈；状态区和操作按钮不触发误勾选。
- 同时覆盖 QCheckBox 与 QAbstractItemView 的勾选项。需要 delegate 时共用相同尺寸与绘制逻辑，避免列表勾选框仍使用另一套外观。
- 通过 Qt 原生绘制或可缩放图形资源绘制勾形，避免依赖字体中的特殊勾号字符。

## 列表、表格与下拉框

### 列表与表格

- 名称、任务、角色等核心列获得扩展空间；序号、状态、计数列按短内容分配有界宽度。
- 名称列宽以 200–240 为常规起点，再按实际内容和窗口预算调整；不能因为当前没有数据而缩到仅容纳表头。
- 模板路径默认以文件名或省略形式展示，完整路径放工具提示或选中项详情。为该列设置上限，不让它自动吃掉全部剩余空间。
- 缩略图列按缩略图实际尺寸规划，统一行高；不依赖 ResizeToContents 反复改变布局。
- 普通业务列表优先让名称完整可读，必要时换成两行；多字段行拆分名称、模式、状态，避免用一串文本加空格拼接。
- 日常页以“序号 / 启用 / 任务名称 / 模式 / 状态”组织每一行，状态按列对齐；拖动排序和勾选行为保留。
- 无数据也保留合理列宽和简短空状态，不能让空表格只剩拥挤的表头。
- 主要列表的高度随剩余空间增长。减少上方多排工具栏与常驻说明，优先保证可见数据行数。
- 只有确实依赖完整多列数据的表格允许水平滚动；任务名称与主要状态应在普通窗口下直接可见。

### 下拉框

- 不把所有下拉框设成相同宽度：短状态选项可紧凑，角色、清单和副本选择以 240–320 为常规起点。
- 闭合控件考虑文本、箭头、边框和左右内边距；弹出列表可宽于闭合控件，并限制在当前屏幕范围内。
- 动态长文本使用字体度量设置有界的 minimumContentsLength / sizeAdjustPolicy，不允许一个异常长选项撑大整个窗口。
- 自由点击页的清单选择独占主要宽度；新建、重命名、删除在窄窗口移到下一行。

## 页面空间分配

统一任务页结构：页面标题与简短状态 → 开始/停止及窗口选择 → 主体参数与列表 → 全局日志抽屉。

- 页头和关键操作有足够高度，停止操作可直接到达。
- 主体超过可用高度时启用垂直滚动；用最小尺寸和 size policy 阻止控件缩到文字以下。
- 次要信息和详细标定清单折叠，错误与缺失条件以简短状态就近显示。
- 日志保持一个全局入口，默认收起。展开时有有界高度，不能把主体压到不可用。
- 横向工具栏根据实际内容需求拆行；宽度阈值以主体可用宽度为依据，不只看主窗口宽度。
- 侧边导航在小高度下可滚动，底部常用操作独立停靠，不能用压缩导航文字来适配。
- 默认窗口大小可以微调，但 1120×720 和既有 800×640 必须分别有可用布局；扩大窗口不能作为唯一修复。
- 复杂页面控制滚动层级：主要列表保留数据滚动，外围内容尽量通过重排和折叠减少长距离嵌套滚动。

## 配色方向

建议以浅色工作台作为新的视觉基准，提供更明亮的深色方案；已有用户的明确外观选择继续生效。
以下是初始色板，落地时对实际相邻颜色和所有状态逐一计算对比度。

| 语义 | 浅色基准 | 明亮深色 |
| --- | --- | --- |
| 应用底色 | #F3F6FB | #181F2A |
| 导航底色 | #E9EFF7 | #1C2532 |
| 主内容面板 | #FFFFFF | #222D3D |
| 输入区域 | #FFFFFF | #1B2533 |
| 正文 | #1F2937 | #EDF2F8 |
| 次级文字 | #526176 | #B8C4D6 |
| 控件关键边界 | #7D8BA0 | #7D8BA0 |
| 装饰性分隔线 | #D4DCE8 | #435167 |
| 主操作与焦点强调 | #2563EB | #82AAFF |
| 主操作上的文字 | #FFFFFF | #172132 |

控件关键边界与装饰分隔线使用不同令牌，避免全界面都画深框。
正文对实际背景至少 4.5:1，关键图标、勾选状态和用于识别控件的边界至少 3:1。
成功、警告、错误使用语义颜色并配合“已完成 / 缺少标定 / 失败”等文字；每个主题分别选合适亮度。

按钮分为主操作、次操作和危险操作。主要开始按钮明确突出，停止在运行时清晰可见；删除与停止不共用主操作颜色。
选中行使用浅强调底色和清楚的前景色；禁用控件使用独立 Disabled 调色板，仍应能读出标签。

主题实现改为语义令牌生成 QPalette 与样式表，主题切换统一刷新。
逐步取消页面复制颜色和按十六进制字符串替换颜色的方式；角色状态与日志颜色也纳入语义令牌。

## 验收标准

- 窗口：1120×720、800×640，以及 1366×768 和 1920×1080 屏幕工作区内的可用窗口。
- 缩放：Windows 100%、125%、150%、200%；高缩放时按真实可用逻辑空间验证，不要求超出屏幕的固定窗口尺寸。
- 文本：正常与较长角色名、清单名、路径、错误信息；不重叠、不裁切，不通过缩小字号解决。
- 控件：表单文字有足够上下留白；未选复选框清晰；选中、焦点、禁用、半选（适用时）可辨识。
- 数据：0 项、1 项、多项；列表表头、名称和状态均合理分配空间，名称列不因空数据塌缩。
- 页面：全部导航页、标定和物品弹窗、悬浮窗；检查日志展开/收起以及运行、停止中、失败等状态。
- 交互：Tab 顺序合理，Space 切换勾选，焦点明确；长名称和细节可通过工具提示或选中详情读取。
- 回归：现有相关 Qt 测试；新增测试只覆盖必要的几何约束、窄窗口可达性和主题状态，不测试每个颜色常量或固定截图像素。
- 视觉检查：截图审阅和 Windows 真机复核均完成，不能只以逻辑单元测试通过作为 UI 验收。

## 实施与验证记录

- 公共层：`theme.py` 统一语义色板、字体、控件状态、20px 勾选框与主题刷新；`widgets.py` 提供可换行工具栏、有界下拉框、可换行表单和名称优先的表格。
- 页面层：任务主体使用滚动区域，开始/停止保留在主体外；全部导航页、标定与物品弹窗、角色栏、日志和悬浮窗完成迁移。名称列至少 200px，路径显示文件名并通过工具提示保留完整路径。
- 功能补齐：在“通用 / 工具”和“角色与窗口”页接回“唤出所有游戏窗口 / 关闭所有游戏窗口”。唤出复用 `wake_all_to_front` 并在窗口前台读取姓名；普通启动/刷新仍只读取身份缓存。一键登录完成继续使用既有身份核验。关闭保留确认、先停止任务及后台关闭进程；取消不停止任务、不关闭游戏。窗口操作期间阻止重复操作、新任务和标定。
- 默认新配置使用白天主题；已有配置的明确外观选择继续生效。真实配置、标定数据和任务执行逻辑未修改。
- Qt 回归覆盖 8 项可读性测试、8 项窗口工具测试和 7 项字段交互测试，包含窄窗口可达性、缩放工作区约束、表单与列宽、工具栏换行、鼠标/键盘勾选、主题切换与颜色对比、窗口管理，以及聚焦/未聚焦和 Ctrl+滚轮不改值、页面继续滚动、左右增减按钮保存/边界/只读、数值与单位分离保存、滚动条实际点击。系统窗口和 OCR 使用替身，不对真实游戏窗口操作。
- 完整回归：`python -m unittest discover -t . -s tests`，580 项通过（99.207 秒）；字段控件收紧后也已按四档缩放复查布局，最后两处横向行对齐调整另跑 Qt 全集并通过。
- 布局检查：四档 Qt 离屏缩放（100%、125%、150%、200%），每档 60 个场景，共 240 个场景；覆盖 12 个导航页、明暗主题、两种窗口尺寸、零/多个角色和日志展开/收起，未发现检查规则内的控件高度不足或主体横向溢出。另审阅标定、物品弹窗与悬浮窗截图。
- 接回窗口工具后，补跑 100% 与 200% 共 120 个场景，未发现上述布局问题，并审阅 800×640 下两个入口页的截图。
- 检查使用隔离配置和示例角色，未启动游戏任务。Windows 原生多显示器切换、真实桌面字体/DPI 与实际任务运行仍需真机复核；离屏场景通过不表示这些环境已验证。
