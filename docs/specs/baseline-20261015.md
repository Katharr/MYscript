- 测量对象是现有 `mhxy.gui.app.App` 主窗口。每个样本由独立 Python 进程启动，

## 指标和步骤

1. 关闭所有目标游戏窗口，运行 `python docs/specs/measure_baseline.py`。
2. 每个动作先预热 1 次，再记录 5 次有效样本。脚本等待 Tk 首次事件循环完成，
   将主窗口可操作定义为冷启动结束点。
3. 首次打开页面测量从已显示的 `general` 页切到尚未创建的 `sniper` 页。
4. 重复切页先创建全部页面，再执行 `general → sniper → treasure_map → escort →
   secret_realm → dungeon → freeclick → settings → about` 共 5 个循环。
5. 展开完整界面测量 `App(compact=True).enter_full()`；恢复悬浮窗先收起，再测量
   `close_float_log(save=False)`。`save=False` 防止写配置。
6. 工作集是每个动作结束时的进程当前 Working Set；主线程卡顿是 5ms `after` 心跳
   观测到的最大超额间隔。耗时单位为 ms。

## 三个游戏窗口（未测）

测量时按当前配置的标题和进程白名单枚举到 **0 个**目标窗口。脚本对该场景返回
`unavailable`，不会把无窗口结果冒充三窗口数据，因此没有中位数或最大值。

有三个窗口时的人工/自动步骤如下：

1. 启动三个真实游戏窗口并登录，确认它们都可见且标题包含 `config.json` 的
   `window_title`，进程名符合 `window_process`。
2. 从项目根目录运行同一命令；脚本仅在恰好检测到 3 个目标窗口时记录样本。
3. 等待一轮预热后重复上述 5 个动作各 5 次，将输出 JSON 的 `three-game` 数组填入
   本表，并重新计算中位数和最大值。
