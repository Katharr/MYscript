# 右侧日志布局修改方案

状态：已落地 Qt 界面；采用「紧凑侧栏 · 脚本优先」。

本轮修订：日志默认宽度由 364 缩至 280，最小宽度由 320 缩至 240；释放的 84 逻辑像素全部归脚本。脚本继续保持原有参数布局、列表列结构与字号，日志不得驱使脚本降字号或隐藏业务列。

## 推荐方案

主窗口改为「左侧导航 / 中间脚本 / 右侧全局日志」。日志与中间的角色条顶部对齐，延伸到状态栏上方。脚本参数、列表独立使用完整纵向空间。

原先 `window.py` 把全局 `LogPanel` 放在脚本纵向布局末尾；`log_panel.py` 又把正文限制在 96–180 逻辑像素。现通过 `LogWorkspace` 水平分栏，侧栏正文取消高度上限；独立任务页仍可使用原嵌入模式。

方案预览使用虚构角色与日志，仅演示布局与视觉层级。

## 布局与尺寸

- 默认窗口加宽为 1440×720，最小仍为 800×640；所有尺寸按 Qt 逻辑像素计算，不重复乘 DPI。已有窗口尺寸记忆继续生效，屏幕不足时仍按工作区缩小。
- 默认 1440 宽度的横向预算：导航 160 + 间隔 16 + 脚本 960 + 分隔手柄 8 + 日志 280 + 右边距 16 = 1440。缩至 1120 宽时脚本为 640，日志仍为 280。
- 中间角色条与任务页属于同一列，右侧日志为全局共用，不随页面切换而清空或更换来源筛选。
- 通过水平 QSplitter 调节脚本与日志比例。日志初始宽 280，允许在 240–320 范围内调整；脚本主体以 640 为最低舒适宽度，复杂页面按原布局实际需要提高下限。额外宽度全部优先分给脚本，日志不按比例膨胀。日志向左拖动遇到脚本舒适下限即停止。
- 原来 1120 宽主窗中的脚本列约 928 宽；新默认 1440 宽主窗可同时容纳 960 宽脚本与 280 宽日志。用户缩窄窗口后，如果某页面需要更大的脚本宽度，优先让日志以右侧抽屉显示。
- 内容区上下边距 16；普通分组间距 12；日志内边距 12。以细分隔线区分区域，减少重复卡片、嵌套边框和装饰空白。
- 沿用现有浅色 / 深色语义色板，普通信息使用正文色，命中 / 成功使用绿色，警告用琥珀色，错误用红色；来源与时间为可读的次要文字。级别同时保留文本标识，不能只靠颜色判断。

## 右侧日志结构

1. 第一行：日志 / 清空 / 收起。使用短标题，移除现有「日志」与「运行日志」重复标题。
2. 第二行：来源筛选 / 跟随最新。筛选框使用剩余宽度，不继承普通表单的固定字段宽度；空间不足时换行。
3. 正文：取消 180 高度上限，垂直填满剩余空间；保留连续文本、选中复制与原生滚动，不把每条日志做成卡片。
4. 底部：当前筛选记录数 / 跟随状态。浏览历史时有新消息，显示「N 条新日志」按钮，点击后回到末尾。

日志排版：保留现有 11pt 正文字号，时间使用等宽数字。以「时间 + [来源] + 正文」连续段落排布，长日志自然换行；续行使用正文全部可用宽度，不为时间单独保留固定列。来源很长时允许完整换行。不要给每条记录增加独占的来源标题行，也不要缩小字号换取密度。紧凑日志会增加长消息的换行，这是保证脚本视觉空间的明确取舍。

时间为新增的 UI 接收时间，缓存一次后复用；切换来源、主题或重绘不能重新生成。保留原消息内容，避免已有时间戳重复。具体文本度量后，常规行距以 22–24 逻辑像素作为起点。

以 1120×720 为验收尺寸，日志区目标容纳约 22–26 个可见文本行；长消息换行会减少可见记录数。这是设计目标，实施后按实际字体与 DPI 截图确认，不承诺固定条数。

## 交互

- 首次使用默认展开右侧日志；后续恢复用户的展开状态与拖动宽度。
- 收起后在右侧保留 40 宽的日志入口，显示未读警告 / 错误数量。普通日志不主动抢占空间，错误不强制展开。
- 默认跟随最新。向上滚动阅读历史或选择文本时暂停跟随，追加消息不移动阅读位置；回到末尾或点击新日志按钮后恢复。
- 切换来源先显示该来源末尾；清空同步清理计数与未读状态。继续保留现有来源筛选和 5000 条有界缓存；新增展示元数据也必须随缓存淘汰。
- 切页沿用全局日志和筛选。悬浮信息条继续复用现有消息信号。

## 窄窗口与高缩放

不能在窄窗口下硬塞三列。按内容区可用宽度决定展示方式：当无法同时容纳当前页面所需的脚本舒适宽度（至少 640）、手柄 8、日志最小 240 时，切换为右侧抽屉模式。页面宽度需求应由现有参数、列数与控件度量确定；复杂页面可更早进入抽屉，不能为保留日志而压坏脚本布局。

- 抽屉模式默认收起为 40 宽右侧入口，脚本使用其余宽度。
- 点击后从右侧覆盖展开约 280 宽日志，不改变脚本布局，也不恢复底部日志；日志宽度不超过可用区域，保留明确关闭按钮与 Esc 收起。
- 抽屉仅在用户主动打开期间覆盖页面；急停快捷键一直有效。
- 从窄窗恢复宽窗时还原宽窗的用户偏好，不用自动收起状态覆盖原有设置。
- 需要按实际字体对工具栏、数值框、列表列宽做 reflow；页面宽度不够时拆行，不能通过继续缩字体解决。

会话里的窄屏预览为便于阅读采用上下重排；真实桌面实现采用本节的右侧覆盖抽屉。

## 备选方案

「紧凑任务旁栏」：角色条横跨脚本与日志，日志从任务页顶部开始。优点是全局选窗更显眼；缺点是角色条增加高度时，日志可用高度随之减少。推荐「紧凑侧栏 · 脚本优先」，默认日志 280，脚本获得其余宽度。

## 实施范围

| 文件 | 修改内容 |
| --- | --- |
| `mhxy/qtui/window.py` | 将中心脚本区域包装为 QWidget；接入 LogWorkspace，切页时更新脚本宽度预算，关闭时保存布局偏好 |
| `mhxy/qtui/log_workspace.py` | QSplitter、右侧日志入口、窄窗覆盖抽屉和 QSettings 布局偏好；封装为单个展示控件 |
| `mhxy/qtui/log_panel.py` | 支持侧栏展示模式，取消侧栏正文高度上限；重排工具栏；增加跟随控制、未读与接收时间元数据；保留独立任务页的既有嵌入模式 |
| `mhxy/qtui/theme.py` | 补充分隔手柄、侧栏、抽屉、日志间距令牌，沿用现有色板与字体 |
| Qt 日志及布局测试 | 覆盖消息流、筛选 / 清空 / 缓存淘汰、暂停跟随、状态恢复、窄窗切换与急停可达性 |
| `docs/specs/12-ui-readability-redesign.md` | 落地时将默认底部抽屉的旧约定同步为本方案 |

QSettings 仅保存界面状态。任务配置、运行事件格式与线程消费入口继续复用现有机制。

右侧布局、伸缩与窄窗退化，以及日志跟随与排版细节均已实现。新增 `tests/test_qt_right_log.py` 验证宽度分配、窄窗状态恢复、Esc 收起、未读计数、有界元数据、滚动与选择保留。

## 验收

- 1120×720 下普通页面脚本目标宽 640、日志宽 280；1440×900 下增加的宽度归脚本，日志保持 280。复杂页面若无法保持原有结构则提前切换抽屉；800×640 下右侧抽屉可用。
- 日常列表保留「序号 / 启用 / 任务名称 / 模式 / 状态」五列；任务页参数布局、主要按钮尺寸与字号保持，不能靠隐藏列或缩字容纳日志。
- Windows 100%、125%、150%、200% 缩放下无文字截断、工具栏重叠或超出屏幕；浅色与深色均检查。
- 长角色名、长来源、连续多行错误、无日志、5000 条日志情况下布局与选择复制正常。
- 用户正在阅读旧日志时追加消息，不跳到末尾；回到最新后恢复跟随。
- 切页、恢复窗口、收起 / 展开和悬浮条消息不丢失、不重复消费。
- 按仓库约定从项目根目录运行 `python -m unittest discover -t . -v`，并补充真实 Qt 窗口截图检查。
