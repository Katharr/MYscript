# UI 3.0 真机视觉修正方案

状态：2026-11-13 根据真机反馈与用户确认形成的实施规格，待实施。标定交互优化已由用户移出本轮。视觉真源为 [UI 3.0 视觉与布局规范](../视觉设计规范.md)，本规格补充 [3.0 基础规格](21-ui-v3-spec.md)的本轮范围与验收。

## Problem Statement

正式 Qt 界面经过首轮改造仍未达到已确认的浅色 3.0 预期。部分中文小字有明显颗粒与缺笔感；唤出、全关、日志等按钮缺少可辨认的边界，日志左侧还有突兀竖线；单项任务标签下出现贯穿整排的长实线。右侧日志从角色条下方开始、阅读区域窄小，并同时提供顶栏日志和面板收起两个入口。

这些问题已在正式 Windows Qt 窗口截图中观察到。此前行为测试通过不能证明真机视觉合格，字体问题的具体渲染原因仍未定位。用户要求先解决现有 UI，不在本轮调整标定中心的入口或流程。

## Solution

保留浅色 3.0 的导航、任务组织与视觉方向，统一修正文字清晰度、按钮边界和标签选中线。将日志调整为右侧全高区域，与应用客户区顶部、底部对齐；默认宽度约占导航以外工作区的三分之一，支持拖动调整。窄窗以全高覆盖方式展示，不压坏参数区，同时保持日志切换、窗口操作与停止任务可达。

顶栏同一个日志按钮负责展开与收起，取消日志面板内重复收起入口。标定中心维持现有操作流程；全局字体、按钮样式修正自然覆盖其界面，不新增标定交互。

## User Stories

1. 作为使用者，我希望继续使用已确认的浅色 3.0，以便修正后的界面保持熟悉。
2. 作为使用者，我希望中文正文和小字笔画清楚，以便无需放大就能阅读。
3. 作为使用者，我希望标题、表单、导航和日志的字体一致协调，以便快速理解信息层级。
4. 作为使用者，我希望系统缩放后文字仍清晰，以便在自己的 Windows 显示设置下使用。
5. 作为使用者，我希望字体调整后文字不被截断，以便读到完整参数与状态。
6. 作为使用者，我希望按钮静止时就有清晰细边框，以便辨认可以点击的区域。
7. 作为使用者，我希望唤出、全关和日志具有一致的尺寸与边界，以便快速找到全局操作。
8. 作为使用者，我希望日志前没有装饰竖线，以便顶栏简洁。
9. 作为键盘使用者，我希望按钮有明确焦点，以便确认下一次操作对象。
10. 作为使用者，我希望普通、悬停、按下、禁用和选中状态清楚，以便判断控件是否可用。
11. 作为使用者，我希望当前任务标签只用文字下方短细线标识，以便明确当前任务而不被粗长线干扰。
12. 作为使用者，我希望未选中标签下没有贯穿整排的粗实线，以便保持页面轻盈。
13. 作为使用者，我希望切换任务后参数、模式和启动对象仍一致，以便避免运行错任务。
14. 作为键盘使用者，我希望标签继续支持方向键与 Home / End，以便快捷切换任务。
15. 作为使用者，我希望运行和停止中仍锁定任务切换，以便保持当前执行对象稳定。
16. 作为使用者，我希望日志从应用内容顶部延伸到底部，以便利用完整窗口高度阅读。
17. 作为使用者，我希望日志默认有足够宽度，以便减少长消息的频繁换行。
18. 作为使用者，我希望拖动调整日志宽度，以便按阅读和配置需要分配空间。
19. 作为使用者，我希望重新打开应用后恢复日志宽度和展开偏好，以便减少重复调整。
20. 作为使用者，我希望同一个日志按钮切换展开与收起，以便不用在两个入口间来回寻找。
21. 作为使用者，我希望收起日志后空间回到业务页面，以便编辑任务参数。
22. 作为使用者，我希望窄窗日志覆盖展开，以便参数控件不被强行压窄。
23. 作为使用者，我希望日志覆盖时仍能操作日志开关、唤出与全关，以便随时管理窗口。
24. 作为使用者，我希望日志覆盖时急停仍可见可点，以便及时停止任务。
25. 作为键盘使用者，我希望 Esc 可收起日志并将焦点返回日志入口，以便继续操作。
26. 作为使用者，我希望窄窗临时收起日志不改掉宽窗偏好，以便恢复宽窗后继续原布局。
27. 作为使用者，我希望切页和展开日志不丢失消息或筛选条件，以便持续追踪运行情况。
28. 作为使用者，我希望查看旧日志时新消息不抢走阅读位置，以便排查问题。
29. 作为使用者，我希望来源筛选、复制、清空、跟随和未读提示继续可用，以便保留现有日志能力。
30. 作为使用者，我希望全关继续要求确认，以便避免误关游戏窗口。
31. 作为使用者，我希望顶部角色选择与队长状态仍完整可用，以便明确任务目标。
32. 作为使用者，我希望本轮保留现有标定入口、流程与资产，以便先获得 UI 修正而不重新学习标定。
33. 作为使用者，我希望开发侧自行截取正式 Qt 真机画面并对比，以便不再由我代为收集基础截图。
34. 作为使用者，我希望最终结果经过实际窗口与系统缩放检查，以便看到的界面与验收结论一致。

## Implementation Decisions

按以下顺序实施，每一步均以现有 Qt Widgets 界面为基础。

1. **建立真机基线并定位字体问题。** 在日常一条龙、单项任务、角色与窗口、标定中心和日志区域采集修正前画面，记录实际 Windows 缩放、字体与启动入口。核对字体回退、字号和字重、字体绘制策略、样式表覆盖及 DPI 初始化路径；区分屏幕渲染问题与截图采样问题。根据原比例真机对比选择修复，不预先将原因判为关闭抗锯齿，也不通过整体缩小或放大截图掩盖缺陷。字体调整集中在主题层，控件尺寸随实际字体度量增长，避免重复计算系统缩放；不修改用户 Windows 字体或显示设置。
2. **统一按钮和标签视觉。** 普通按钮采用已有语义色中的清晰细边框，覆盖顶栏与业务页常见按钮；保留主操作、危险动作和键盘焦点的区别。移除日志前装饰竖线。任务标签仅保留文字下方短细选中线，排除原生标签基线与自定义边线叠加产生长线的情况；保留原生标签的可访问名称、鼠标、键盘、滚动和运行锁定行为。
3. **调整主窗口与日志的布局边界。** 将顶栏、角色条和当前业务页面组织在左侧工作区，右侧日志作为全高同级区域；日志顶部和底部与应用可布局客户区对齐，不延伸进系统标题栏。现有全局状态栏如需保留，位于左侧业务区，不能让日志底部重新缩短。沿用既有日志布局与面板模块，不新建第二套日志消费或消息存储。
4. **落实日志宽度与窄窗规则。** 默认约占导航以外可用工作区三分之一，宽窗支持拖动并恢复用户宽度；具体上下限按真实字体和控件最小尺寸计算，不把原 236 像素限制继续当作目标。当页面最小需求与日志宽度不能同时满足时，进入右侧全高覆盖模式，保持业务页布局尺寸；全局按钮行及必要停止操作保留在可达层，覆盖层对这些操作让位，不靠增加第二个收起按钮解决遮挡。临时窄窗状态不覆盖宽窗偏好。
5. **统一日志入口与焦点。** 保留顶栏同一个日志切换按钮，其选中状态与当前可见状态同步，文字或可访问名称明确对应动作；取消面板内重复收起按钮和旧折叠轨上的第二入口。收起后焦点返回该按钮；展开后焦点进入可读日志区域，Esc 收起。未读警告 / 错误通过保留的入口表达，不强制展开，不丢失现有未读语义。
6. **保留既有契约并完成回归。** 日志复用单一消息流、有界缓存、筛选和阅读状态；角色选择、运行快照、全关确认、默认演练及配置保存护栏保持原有行为。界面设置沿用原有独立存储，正常范围内的既有宽度偏好继续兼容。标定中心不做入口简化、列表重组、预览确认或连续标定；保留工作区现存的用户改动。界面文案继续只出现控件名、状态和必要错误 / 安全提示。

## Testing Decisions

- 主要测试边界为**正式 Qt 主窗口的用户操作与可见结果**，复用现有真实 Qt 组件、临时配置、临时界面设置、虚拟窗口与模拟任务；不新增用于本轮修正的公共测试接口。此前已明确验收方式由开发侧确定，本方案沿用该入口，无需再访谈测试偏好。
- 既有依据为 [3.0 工作台回归](../../tests/test_qt_ui_v3.py)、[右侧日志回归](../../tests/test_qt_right_log.py)、[可读性回归](../../tests/test_qt_readability.py)、[窗口操作回归](../../tests/test_qt_window_tools.py)及现有日志行为、统一选窗回归。旧测试中固定 236 像素、角色条横跨日志上方、覆盖层起于顶栏下方、通过面板内收起按钮操作等断言随新契约替换，保留其余行为保障。
- 布局断言比较主窗口坐标中的日志上下边界与客户区边界，不能只断言日志在自己的局部父容器内从零开始。检查全高、宽度拖动、首用比例、重启恢复、宽窄切换，以及覆盖模式下实际命中测试与按钮可点击性；仅检查 `isVisible()` 不足以证明未被遮挡。
- 通过顶栏唯一日志按钮和 Esc 驱动展开 / 收起，验证选中状态、焦点返回、未读提示、切页保留、筛选 / 复制 / 清空、跟随暂停和恢复、缓存上限、不丢失或重复消息。现有面板级日志测试继续使用，无需为每个布局层新增同类测试。
- 标签继续验证鼠标和方向键、Home / End、不同任务参数保留、面板和启动对象一致、运行和停止中禁用。按钮验证正常 / 禁用 / 焦点状态及全关确认取消；使用窗口服务替身，不在自动测试中关闭真实游戏。
- 在 1120×720、800×640、较大窗口及 Windows 100%、125%、150%、200% 缩放下检查日常、单项任务、通用工具、角色与窗口、设置及标定现有页面；覆盖长角色名、无角色、多角色、长错误和长日志，以及空闲 / 运行 / 停止中。自动缩放检查需使用独立进程，不能把离屏 Qt 缩放等同于真实 Windows 缩放。
- **视觉验收独立于行为测试。** 开发侧自行截取正式 Qt 在真机上的修正前后画面，按原比例核对字体笔画、按钮边界、竖线消除、标签短线与日志全高；需要裁剪放大时保留原图作依据。不得以样式字符串断言、测试数量或 HTML 原型截图代替实际视觉验收。无法覆盖的真实系统缩放档位如实列出，不宣称通过。
- 实施时先执行涉及模块的回归，再运行项目统一全量回归 `python -m unittest discover -t . -v`，使用测试包的真实配置隔离。文档交付只验证引用、范围和一致性，不为本次纯文档修改运行或编写 UI 测试。

## Out of Scope

- 标定中心操作优化整体延期：不改任务选择入口，不重排标定项，不增加逐项预览确认、缺失项引导或连续标定，不改通用标定 / 专属标定语义与保存事务。全局字体及按钮样式带来的外观修正仍属于本轮。
- 不重做原型、不改变已确认的浅色方向，不新增 Web、QML、第三方控件框架或主题库。
- 不调整任务、识别算法、输入方式、窗口身份、队伍规则、配置结构或标定资产，不删减完整参数与功能。
- 本次请求交付修改方案与契约更新，不实施生产代码、不打包发布、不提交或推送现存工作区改动。
